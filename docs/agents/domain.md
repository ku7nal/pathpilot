# Domain Docs

Before exploring, read `CONTEXT.md` at the repo root, or `CONTEXT-MAP.md` if it exists, and read relevant ADRs under `docs/adr/`. In a multi-context repo, also check context-scoped ADRs.

If these files do not exist, proceed silently. Create domain documentation only when domain terms or decisions are resolved.

Use glossary terms from the relevant `CONTEXT.md`. If a needed term is missing, note the gap. Surface conflicts with relevant ADRs rather than silently overriding them.

This repo uses a single-context layout: one root `CONTEXT.md` and `docs/adr/`.
